# astrbot_plugin_ppm

PPM 是一个运行在 AstrBot WebUI 内的项目进度管理插件，覆盖团队成员、公司考勤、项目状态与人员变动追溯、每日工作记录、跨项目进程表和 AI 日报。

## 功能

- 团队成员：新增、编辑、软删除成员，按准备、进行、维护、暂停、结束展示参与项目数量；可在居中窗口查看项目明细。
- 公司考勤：按中国法定工作日生成月历，依赖不可用或年份超出支持范围时退化为周一至周五；管理员可逐日覆盖上班/休班。
- 成员考勤：法定工作日默认正常出勤，只需登记加班、调休或特殊正常出勤；按项目状态历史逐日计算，进行状态计入“项”，维护状态仅在该项目当天有工作记录时计入“项”，否则按普通出勤显示“勤”；准备状态同样按普通出勤处理，并提供月度汇总和异常明细。
- 项目管理：支持 `准备 / 进行 / 维护 / 暂停 / 结束`，每个项目使用不可修改的纯数字项目 ID，并完整记录状态变化和成员加入/退出历史。
- 每日进展：按项目、日期记录工作内容，可在跨项目日期矩阵中查看。
- 待办事项：关联项目、填写待办内容；支持项目筛选、一次性推送、按星期设置周期推送和推送结果查看。
- AI 日报：使用 AstrBot 已接入的聊天模型，默认勾选总结日期当天有工作记录或任务变更的项目，不受状态限制，附带历史总结默认 1 天。可在项目进程相同的时间范围内查看生成状态，每天只保存一份，并支持预览覆盖、人工修订和删除。

## 安装与配置

1. 将仓库目录放到 AstrBot 的 `data/plugins/astrbot_plugin_ppm`。
2. 法定节假日库为可选依赖：如需使用中国法定节假日数据，请在 AstrBot 运行环境安装 `chinesecalendar>=1.11.0`；未安装时插件会按周一至周五规则运行。该库不再作为插件强制依赖，避免依赖安装失败阻断插件加载。
3. 在插件配置中选择“日报总结模型”，该选项来自 AstrBot 已配置的模型提供商。
4. 重载插件，在插件详情页打开 `ppm` Page。

数据库自动创建在：

```text
data/plugin_data/astrbot_plugin_ppm/ppm.sqlite3
```

更新或重装插件不会覆盖此目录。建议将该 SQLite 文件纳入日常备份。

## 目录结构

```text
main.py                    # AstrBot 生命周期和依赖装配
ppm/
  database.py              # SQLite schema、仓储和业务规则
  calendar_service.py      # 法定日历与工作日回退逻辑
  todo_service.py          # 持久化待办提醒、失败重试与停机处理
  validation.py            # Web 输入验证
  web_api.py               # AstrBot Page API 适配层
pages/ppm/
  index.html               # 页面语义结构
  style.css                # 设计系统和响应式布局
  app.js                   # bridge、状态与交互
tests/test_database.py     # 核心业务回归测试
```

页面和业务服务之间只通过 JSON API 通信；消息指令直接复用 `Database` 服务，不需要依赖 WebUI 代码。

## 待办与定时推送

1. 在目标群聊或私聊向 AstrBot 发送 `/sid`，复制完整 UMO（`平台ID:消息类型:会话ID`）。在插件配置的“待办推送会话 ID（UMO）”中填写，保存并重载插件。所有待办提醒使用这个目标会话；不能只填写群号或用户号。
2. 打开“待办事项” → “新增待办”，选择所属项目并填写内容。待办不设执行状态，页面只保留内容、所属项目、推送安排和编辑／删除操作。
3. 开启推送后选择方式：**一次性推送**填写具体日期时间；**周期推送**勾选每周需要提醒的星期，再设置固定时刻。“全选（每天）”会选中周一至周日。例如周一、周三、周五 09:00，只在这三天推送。
4. 一次性时间按浏览器本地时区输入，转换为 UTC 保存。周期时间使用创建或切换到周期模式时浏览器的固定 UTC 偏移量（如 UTC+08:00），编辑时保持原时区；页面会明确显示该时区，不会随服务器或其他设备时区改变，也不会自动切换夏令时。
5. 页面显示推送安排、周期提醒的下次时间、上次发送时间及失败原因。关闭推送可暂停，删除待办或删除所属项目会停止后续提醒。

提醒服务每 15 秒检查一次数据库。一次性提醒成功后不再发送；周期提醒成功后自动安排下一个选定星期的同一时刻。失败一分钟后重试，修改内容不会重复已发送的一次性提醒，也不会改变已有周期提醒的下次时间。修改推送安排或关闭后重新开启会重新计算。

重启后一次性提醒会补发尚未成功的到期提醒；周期提醒跳过往日错过的提醒，不集中补发历史记录，当天已安排但未发送的提醒可在恢复后发送一次。已开始发送的消息不能撤回，发送期间编辑或删除会提示稍后操作。

未配置会话仍可保存待办，页面会提示补充配置。平台需支持 AstrBot 主动消息；发送成功表示接口调用完成，无法确认收件人已读。若进程在消息发出但结果尚未入库时崩溃，恢复后可能重复提醒。

升级会保留原有待办的一次性推送设置；旧版本“已完成”或“已取消”的待办迁移为关闭推送，避免重新启动提醒。旧的执行状态字段及接口会移除。

接口依据：[AstrBot 主动消息](https://docs.astrbot.app/dev/star/guides/send-message.html)、[会话标识与 /sid](https://docs.astrbot.app/use/command.html)。

## 界面色调

在 AstrBot 的插件配置页面设置「界面色调」，可选森林绿（默认）、海湾蓝、鸢尾紫、暖琥珀。配色覆盖导航、按钮、进度条及任务时间轴，桌面与手机页面共用同一设置。保存后重载插件并刷新页面生效；非法或旧配置值自动回退到森林绿。

## 消息指令

仅保留生成每日总结的消息指令：

```text
/每日总结
/每日总结 1
/每日总结 0 12 18
```

第一个参数是附带前几天总结的天数（0～30，默认 1），后面可选项目 ID。不填项目 ID 时，默认选择当天有工作记录或任务变更的项目，不受项目状态限制。消息指令会直接覆盖当天已有日报。项目、任务和记录通过 WebUI 维护。

日报按「项目 → 任务 → 当日记录」提供资料，同名任务通过 ID 区分，并单独保留未关联任务的项目级记录。任务状态和进度使用截至总结日期的最后历史快照，避免后来的改名、完成、重开、删除污染历史日报；无当日快照的关联任务标为未知且不计入已知进度。记录内容使用所选日期记录的最新修订。

任务变更时间、完成日期和实际工作记录分别提供：补录以前的完成日期不代表当天完成，任务重开和删除也不算完成成果。没有当日记录的任务仅作背景，历史日报只供衔接，不重复归为今日产出。自定义提示词仍保留，系统会自动补充这些资料解读规则。

项目总结的按钮、API、消息指令和专用提示词配置均已移除。任务生命周期、工作记录及变更历史照常保留。

## 数据模型

### 任务、进度与全生命周期

每个项目可以创建多项任务，任务只有「未完成」「完成」两种状态，与定时推送的「待办事项」独立。项目列表和项目详情显示任务进度：**已完成任务数 ÷ 未删除任务总数 × 100%**，四舍五入到整数；没有任务时显示 0% 和「尚未设置任务」。项目的准备、进行、维护等业务状态仍由人工设置，不随任务进度自动切换。

- **总览与任务**：填写任务名称、说明和开始日期。完成时可指定完成日期，不能早于开始或晚于今天；未来开始的未完成任务显示 0 天。持续天数是开始日至完成日（未完成则至今天）的自然日跨度，含首尾日期，不代表实际投入工时。
- **任务生命周期**：时间条展示每项任务的跨度，圆点对应关联记录的日期。展开任务可查看全部记录和变更历史；完成、重新打开、修改日期以及删除均保留历史快照。重开后当前完成日期清空，之前的完成日期仍可在历史中查看。
- **工作记录**：新增或编辑记录时，可以选择一项同项目任务，也可以保持为项目级记录。保存时可以保持任务状态、标记完成或重新打开；标记完成使用记录日期，记录与状态变更在同一个事务内提交。任务已经完成时再次选择完成不会覆盖原完成日期，修正日期请编辑任务。
- **项目档案**：保留项目基本信息、项目状态历史、成员历史及关联待办。工作记录默认显示全部时间，可按日期和任务筛选。
- **删除与兼容**：删除任务后不再计入进度，任务历史和记录继续保留，可通过「已删除任务」查看。旧记录迁移为项目级记录，可后续补充关联。编辑旧接口未传 `task_id` 时保留原关联，显式传 `null` 可解除关联。删除记录不会撤销已发生的任务状态变更。

新增 API：`GET tasks?project_id=...`、`POST tasks/save`、`POST tasks/delete`。任务编辑及删除需同时携带任务 `id` 和所属 `project_id`；任务保存支持部分字段更新。`worklogs/save` 支持可选 `task_id` 和 `task_action`（`keep` / `complete` / `reopen`）。日报资料包含按日期还原的任务状态、历史快照和记录关联。

升级后首次加载会自动执行增量迁移（SQLite schema v3），添加 `project_tasks`、`task_history` 和 `work_logs.task_id`，保留已有项目、记录、成员及提醒数据。


核心表包括 `members`、`projects`、`project_status_history`、`project_memberships`、`work_logs`、`calendar_days`、`attendance_records`、`team_daily_summaries` 与 `todos`。实体删除采用软删除；状态和成员变动历史支持人工修正，历史表不级联删除。团队日报按日期唯一保存，生成时可附带前 0～30 天的已保存总结，默认 1 天。

考勤约定：一个成员每天只有一个主状态。工作日无记录时为“正常”，参与项目时显示项目标识并可悬停查看项目名称；登记“加班”或“调休”后，该日按对应状态汇总。未来日期不显示成员状态，也不参与统计。

## 开发验证

```bash
python -m unittest discover -s tests -v
python -m compileall -q .
```

直接通过静态服务器打开 `pages/ppm/` 时，页面会使用仅存在于浏览器内存的演示数据，便于视觉开发；在 AstrBot iframe 中会自动切换到 Page bridge 和真实 SQLite 数据。

## 当前边界

- 当前仅注册跨平台消息指令 `每日总结`，由 AstrBot 的消息事件过滤器统一处理。
- 法定节假日取决于 `chinesecalendar` 已收录年份；超出范围时按周末规则回退，并可在 WebUI 人工修正。
- 考勤矩阵按月展示，汇总支持周、月、年；每周起始日遵循插件配置。
